# Workflow ALTER EGO DEV

## Statuts
Idée → Cadrage → Conception → Implémentation → Vérification → Revue → Prêt à fusionner → Livré.

## Fiche de fonctionnalité
- Problème utilisateur :
- Public cible :
- Résultat attendu :
- Inclus / exclu :
- Critères d'acceptation vérifiables :
- Contraintes (plateformes, budget, délais, confidentialité) :
- Dépendances :
- Risques :
- Définition de terminé :

## Contrat de pull request
- Contexte et objectif
- Résumé des modifications
- Captures si interface modifiée
- Tests exécutés (commandes et résultats)
- Tests non exécutés et justification
- Impacts sécurité / données / performances
- Migration et retour arrière si nécessaire
- Questions ouvertes

## Qualité minimale
Une fonctionnalité n'est pas terminée sans critères d'acceptation vérifiés, revue des risques et état réel des tests. Les déploiements nécessitent un accord explicite.

## Premier jalon
Choisir l'application à construire, identifier ses utilisateurs et définir un MVP. Ne pas imposer de framework, base de données ou hébergeur avant ce cadrage.
